# Clipdrop v1 — Master Architecture & 6-Phase Execution Plan

## 1. Executive Summary & Product Vision

Clipdrop is a zero-cloud, peer-to-peer clipboard and screenshot synchronization daemon designed to operate seamlessly across macOS and Windows laptops connected to the same local Wi-Fi network. 

### 1.1 Core Value Proposition
- Instant Screenshot Sharing: A screenshot captured on Windows (Win+Shift+S) or macOS (Cmd+Ctrl+Shift+4) is immediately available to paste on the peer machine in under 2 seconds.
- Bi-directional Text Synchronization: Plain text copied on either operating system is instantaneously synced to the other.
- Absolute Privacy: Zero cloud relays, zero user accounts, zero telemetry, and zero third-party servers. All transfers occur point-to-point over local Wi-Fi.
- Zero-Trust Security: Traffic is encrypted via Mutual TLS 1.3 with pinned ECDSA certificates. Unpaired devices are rejected at the TLS handshake.
- Echo-Proof Engineering: Cryptographic state tracking completely eliminates infinite copy-paste feedback loops.

### 1.2 Non-Goals for Version 1
- No system tray, menu bar applet, or GUI window (strictly foreground CLI in v1).
- No background OS service daemon or autostart installer.
- No cloud relay, internet proxy, or Tailscale integration (strictly local subnet).
- No SQLite database or searchable clipboard history viewer.
- No arbitrary file transfers or folder syncing.
- No multi-peer swarms beyond two paired laptops.

## 4. Phase 1 — Foundation & CLI Skeleton

### 4.1 Objectives & Deliverables
Establishes the application entry point, argument parsing, configuration storage, structured logging, and graceful process lifecycle handling.

### 4.2 CLI Specification
- Framework: Standard library `flag` package (no external frameworks).
- Subcommands:
  - `clipdrop version`: Prints version, commit hash, build date, and protocol version.
  - `clipdrop run`: Runs sync daemon in foreground (Flags: `--images-only`, `--no-text`, `--port`, `--peer`, `--verbose`).
  - `clipdrop pair`: Initiates host pairing mode with a temporary listener.
  - `clipdrop pair join`: Prompts for pairing code and discovers host.
  - `clipdrop devices`: Lists trusted peers with fingerprints and last-seen timestamps.
  - `clipdrop unpair <name>`: Revokes trust for a specified peer.
  - `clipdrop doctor`: Runs system and network diagnostic checks.
- Exit Codes: `0` (Success/Clean Exit), `1` (Runtime Error), `2` (Argument Error), `130` (Interrupted by SIGINT).

### 4.3 Configuration & State Rules
- macOS: `/Users/[user]/Library/Application Support/clipdrop`
- Windows: `C:\Users\[user]\AppData\Roaming\clipdrop`
- Directory Permissions: Mode `0700` (strictly user read/write/execute).
- File Permissions: Mode `0600` (strictly user read/write).

### 4.4 Logging & Lifecycle
- Standard library `log/slog` with dynamic level switching (`INFO` default, `DEBUG` under `--verbose`).
- Strict Data Privacy: Under no circumstances are raw clipboard payloads or pairing secrets logged.
- Process Lifecycle: Root context cancelled on `SIGINT` (Ctrl+C) or `SIGTERM`, providing 3-second graceful drain.

## 5. Phase 2 — Local Core: Clipboard, Imaging & Engine

### 5.1 Objectives & Deliverables
Builds the clipboard abstraction layer, byte-level PNG/text validation routines, and the local event engine with echo-loop prevention.

### 5.2 Clipboard Abstraction
- Platform Interface: `Read()` (returns bytes + classification), `Write()` (applies content), `Watch()` (emits change events over channel).
- Real Implementation: Wraps `golang.design/x/clipboard` with build tags for `darwin` (cgo Cocoa pasteboard) and `windows` (Win32 user32 pasteboard).
- Fake Implementation: In-memory thread-safe mock with event channels for automated testing.

### 5.3 Imaging & Payload Normalization
- PNG Validator: Verifies 8-byte magic header (`137, 80, 78, 71, 13, 10, 26, 10`), parses IHDR chunk, enforces maximum dimensions of 16,384 x 16,384 pixels, and caps payload size at 25 Megabytes.
- Text Validator: Verifies UTF-8 encoding compliance and caps payload size at 1 Megabyte.
- Policy Enforcement: Drops text events when `--images-only` or `--no-text` flags are set.

### 5.4 Echo Loop Elimination Algorithm
- State Tracking: Maintains `CurrentLocalHash`, `LastReceivedHash`, and `LastLocalSentHash`.
- Outbound Filter: When clipboard changes locally, engine computes SHA-256 digest. If digest equals `LastReceivedHash`, the event is recognized as a reflection of a remote write and is immediately suppressed.
- Inbound Guarantee: When receiving a remote item, the engine records its hash into `LastReceivedHash` *prior* to executing the clipboard `Write()`.

## 6. Phase 3 — Identity & Transport Security

### 6.1 Objectives & Deliverables
Establishes decentralized cryptographic identity, pinned certificate trust, and mutual TLS 1.3 HTTP transport.

### 6.2 Identity & Key Management
- Algorithm: ECDSA NIST P-256 keypair (`crypto/ecdsa`) and self-signed X.509 v3 certificate (`crypto/x509`) with 10-year validity.
- Device ID: Hexadecimal SHA-256 digest of the raw DER certificate bytes.
- Storage: Stored at `key.pem` and `cert.pem` inside config directory with strict mode `0600`.

### 6.3 Pinned Trust Model (`trusted_devices.json`)
- CA-less Trust: No external Certificate Authorities. Trust is strictly peer-to-peer.
- Handshake Verification: Custom `VerifyPeerCertificate` callback inspects peer leaf certificate, computes its SHA-256 digest, and checks `trusted_devices.json`. Unlisted certificates are rejected during the TLS handshake.
- Persistence: Atomic writes via temporary file and rename, protected by `sync.RWMutex`.

### 6.4 Sync Wire Protocol
- Protocol Headers: `X-Proto-Version: 1` (required), `X-Sha256` (on binary uploads).
- `GET /v1/ping`: Peer health check returning device name and protocol version.
- `POST /v1/offer`: Pre-flight JSON request (`id`, `kind`, `size`, `sha256`, `mime`). Receiver replies `send` or `skip` (reasons: `duplicate`, `too_large`, `kind_disabled`, `paused`).
- `PUT /v1/items/{id}`: Binary streaming payload upload with streaming SHA-256 verification and PNG validation (Status: `200` OK, `400` Bad Request, `413` Too Large, `422` Hash Mismatch).
- Timeouts: Connect: 3s, Offer: 3s, Upload: 15s.

## 7. Phase 4 — Discovery, Pairing & Sync Pipeline

### 7.1 Objectives & Deliverables
Implements out-of-band PAKE pairing, zero-configuration mDNS discovery, peer presence heartbeats, and the end-to-end sync loop.

### 7.2 PAKE Pairing Ceremony
- Ephemeral Host: Dedicated pairing listener running on a dynamic port with a 120-second expiration timer and 3-attempt brute-force lockout.
- Code Format: `NNNN-word-word` (e.g., `4821-hawk-moon`).
- Protocol: `schollz/pake v3` key exchange deriving a 256-bit symmetric session key.
- Identity Exchange: Mutual transmission of certificate fingerprints, hostnames, and OS types encrypted via AES-GCM.
- Immediate Teardown: Listener terminates and deregisters from mDNS immediately upon successful exchange.

### 7.3 Local Discovery via mDNS Zeroconf
- Service Type: `_clipdrop._tcp` published via `grandcat/zeroconf`.
- TXT Record Attributes: `id`, `name`, `os`, `proto`, `status`.
- Address Resolution Hierarchy: Active mDNS cache → `--peer` flag fallback → stored `last_address`.
- Network Resilience: Re-announces service upon network adapter changes or laptop wake events.

### 7.4 Presence Heartbeat & Synchronization Loop
- Presence Heartbeat: Every 5 seconds, issues `GET /v1/ping` to trusted peers. Logs state changes only (online/offline transitions) to keep logs clean.
- Complete Sync Pipeline:
  1. Watcher detects local copy.
  2. Engine validates, normalizes, hashes, and confirms non-echo/non-duplicate.
  3. Resolver identifies reachable peers.
  4. Client executes `POST /v1/offer`.
  5. If accepted, client streams bytes via `PUT /v1/items/{id}`.
  6. Remote server validates hash/PNG, records `LastReceivedHash`, and writes to clipboard.

## 8. Phase 5 — Diagnostics, Doctor & Documentation

### 8.1 Objectives & Deliverables
Delivers the `clipdrop doctor` diagnostic engine, received items retention management, an optional macOS screenshot folder watcher, and comprehensive technical documentation.

### 8.2 Diagnostic Engine (`clipdrop doctor`)
- Non-destructive diagnostics running with standard user privileges.
- Check Matrix:
  - Config directory existence and mode `0700` permissions.
  - Identity keypair validity and certificate expiration.
  - Trusted devices registry integrity.
  - Port `47820` TCP bind availability.
  - Multicast DNS network interface capability.
  - Trusted peer reachability via ping.
  - Windows: Defender Firewall inbound rule presence and Private network profile check.
  - macOS: System pasteboard accessibility.
- Output: Aligned terminal status table (PASS / WARN / FAIL) with actionable remediation commands.

### 8.3 Received Items Retention Management
- Storage Location: `received/` directory inside configuration path (`0700`).
- File Naming: Chronological timestamp + hash prefix (`YYYYMMDDTHHMMSSZ_[hash].png`).
- FIFO Pruning: Automatically unlinks oldest files to maintain an upper limit of exactly 20 items.

### 8.4 Optional macOS Screenshot Folder Watcher (`--watch-screenshots`)
- Reads system preference: `defaults read com.apple.screencapture location` (fallback to Desktop).
- Debounces file-writing activity (sampling size across 250ms intervals until stable).
- Ingests new PNG screenshots directly into the sync pipeline.

### 8.5 Technical Documentation Suite
- `docs/SPEC.md`: Master architectural specification, invariants, and scope boundaries.
- `docs/protocol.md`: Complete wire protocol reference, custom headers, and JSON schemas.
- `docs/troubleshooting.md`: Operational troubleshooting runbook (Wi-Fi client isolation, firewall rules, permissions).

## 9. Phase 6 — End-to-End Testing & Verification

### 9.1 Objectives & Deliverables
Executes final validation, race condition audits, cross-platform physical tests, fault injection scenarios, and Definition of Done certification.

### 9.2 Concurrency & Race Verification
- Command: `go test -race ./...` executed across all packages on both macOS and Windows.
- Standard: Zero race conditions, zero deadlocks, and zero goroutine leaks.

### 9.3 Physical Cross-Platform Test Matrix (macOS ↔ Windows)
- Test 1 (Pairing): Out-of-band PAKE exchange between Mac and Windows completed in under 15 seconds.
- Test 2 (Mac Screenshot to Windows): Area screenshot (`Cmd+Ctrl+Shift+4`) on Mac pastes in Windows Paint in under 2 seconds.
- Test 3 (Windows Screenshot to Mac): Area screenshot (`Win+Shift+S`) on Windows pastes in macOS Preview in under 2 seconds.
- Test 4 (Text Sync): Plain text copied on either machine pastes on the peer in under 500 milliseconds.
- Test 5 (10-Minute Echo Audit): 30 continuous clipboard updates over 10 minutes with zero feedback echo loops.
- Test 6 (Rapid Copies): Three successive copies within 1 second stabilize cleanly on the latest item.

### 9.4 Security & Resilience Verification
- Intruder Rejection: An unpaired third laptop attempting connection is dropped during TLS handshake.
- Payload Tampering: Modifying bytes in transit results in immediate HTTP `422` hash mismatch rejection.
- Pairing Lockout: Three invalid pairing code submissions trigger immediate host listener shutdown.
- Network Recovery: Toggling Wi-Fi or waking laptop from sleep re-establishes peer sync within 5 seconds without restarting processes.
