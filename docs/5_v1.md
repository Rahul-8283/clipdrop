# Phase 5 — Diagnostics, Doctor & Documentation (v1)

## 1. Document Overview & Goals

### 1.1 Objective
Phase 5 delivers operational reliability, self-service diagnostics, content retention management, and comprehensive documentation for Clipdrop. The core focus is providing operators with a robust diagnostic command (clipdrop doctor) capable of diagnosing local firewall restrictions, port collisions, permission issues, and network isolation problems. Additionally, this phase introduces automatic retention management for received clipboard items, an optional macOS screenshot directory watcher, and a complete documentation suite.

### 1.2 In-Scope Deliverables
- Automated diagnostic engine implemented within doctor/ to validate system health.
- Command clipdrop doctor emitting a structured pass/fail status table with actionable remediation instructions.
- Operating system-specific diagnostic checks for Windows Firewall profiles and macOS permission entitlements.
- Retention manager within store/ to archive incoming items and prune history strictly to the 20 most recent files.
- Optional macOS screenshot folder watcher (platform/screenshots/) activated via --watch-screenshots.
- Creation of the complete technical documentation suite: docs/SPEC.md, docs/protocol.md, and docs/troubleshooting.md.
- Standardized manual testing and pre-release smoke checklist.

### 1.3 Out-of-Scope (Non-Goals for Phase 5)
- No graphical user interface (GUI), web dashboard, or tray icon for diagnostics.
- No automated operating system firewall modification (must display instructions, never elevate privileges silently).
- No infinite or cloud-synced clipboard history.
- No multi-user role-based access control.

## 2. Package Architecture & Responsibilities

### 2.1 Diagnostic Subsystem: doctor/
- checker.go: Declares the diagnostic Check interface, Status enumeration (Pass, Warn, Fail), and result structures.
- runner.go: Executes diagnostic checks in sequential order, gathers execution timings, and compiles final reports.
- checks_core.go: Platform-agnostic checks verifying files, directories, port bindings, and identity validity.
- checks_darwin.go: macOS-specific checks verifying pasteboard accessibility and screencapture location preferences.
- checks_windows.go: Windows-specific checks verifying Windows Defender Firewall rules and active network profile types.
- printer.go: Formats diagnostic results into a clean, human-readable terminal table with remediation hints.

### 2.2 Retention Management: store/ (received/)
- retention.go: Manages the local received/ directory located inside the application configuration folder.
- Enforces an upper ceiling of 20 archived items, automatically pruning the oldest entries upon new item ingestion.
- Sanitizes file naming using timestamp prefixes and cryptographic digests to prevent directory traversal.

### 2.3 Screenshot Directory Watcher: platform/screenshots/
- watcher_darwin.go: Reads the configured macOS screenshot destination from system preferences and watches for newly written image files.
- Implements write-completion debouncing to ensure files are fully written by macOS before ingestion into the sync engine.

## 3. Diagnostic Engine (clipdrop doctor) Specification

### 3.1 Diagnostic Design Principles
- Non-Destructive: Running diagnostics must never mutate configuration, overwrite certificates, or delete user data.
- Actionable Guidance: Every warning or failure must include a concise, step-by-step remediation command or instruction.
- Zero Privilege Escalation: Diagnostics must run with standard user privileges without prompting for sudo or Administrator elevation.

### 3.2 Diagnostic Check Matrix

| Check Name | Target Component | Success Criteria | Failure Remediation Hint |
|---|---|---|---|
| Config Directory | Filesystem | Path exists, writable, permissions are mode 0700 | "Run: chmod 700 [path] or verify disk write permissions." |
| Device Identity | Identity / Crypto | key.pem and cert.pem exist, valid P-256 pair, cert unexpired | "Run 'clipdrop run' to regenerate a fresh device identity." |
| Trusted Store | Store / Registry | trusted_devices.json is valid JSON with valid schema | "Inspect file for JSON corruption or delete to reset pairings." |
| Port Availability | Network Transport | Configured port (default: 47820) can be bound to TCP | "Port is in use by another process. Specify an alternate with --port." |
| Multicast DNS | Discovery / mDNS | Multicast interface is enabled and can bind to 224.0.0.251:5353 | "Local network interface does not support multicast. Use --peer ip:port." |
| Peer Connectivity | Network Transport | Every trusted peer responds to GET /v1/ping within 3 seconds | "Peer is offline, on a different Wi-Fi, or blocked by client isolation." |
| Windows Firewall | OS Network (Windows) | Inbound rule exists for clipdrop.exe on Private profile | "Run PowerShell as Admin: New-NetFirewallRule -DisplayName 'Clipdrop' -Direction Inbound -Program '[path]' -Action Allow" |
| Windows Profile | OS Network (Windows) | Active network connection is classified as 'Private' | "Current Wi-Fi is set to 'Public'. Change network profile to 'Private' in Windows Settings." |
| macOS Permissions | OS Security (macOS) | Process can read system pasteboard without OS security faults | "Ensure Terminal or iTerm2 has permissions under System Settings > Privacy & Security." |

### 3.3 Terminal Output Specification
The output of clipdrop doctor is rendered as an aligned terminal report:
- Header indicating host operating system, current user, and resolved configuration directory.
- Check rows displaying check name, status indicator (PASS in green, WARN in yellow, FAIL in red), latency, and summary.
- Remediation section appended to the bottom listing concrete commands for any flagged issues.
- Overall diagnosis banner indicating whether the system is ready for sync.

## 4. Received Items Archiving & Retention Policy

### 4.1 Storage Layout
When a remote peer sends an item via PUT /v1/items/{id}, a copy is saved locally for operator reference:
- Storage Root: Located inside the application configuration path at received/.
- Directory Permissions: Enforced at mode 0700.

### 4.2 Naming Convention
To prevent collisions and enable chronological sorting:
- Images: YYYYMMDDTHHMMSSZ_[first-8-chars-of-sha256].png
- Text: YYYYMMDDTHHMMSSZ_[first-8-chars-of-sha256].txt
- Example: 20261118T143000Z_e3b0c442.png

### 4.3 Pruning Algorithm
1. After successfully writing a new received item, the retention manager lists all files in received/.
2. Files are sorted chronologically by modification timestamp (oldest first).
3. If the total file count exceeds 20:
   - The oldest files are identified until the count equals 20.
   - The identified files are permanently unlinked from the filesystem.
4. Pruning operations are non-blocking and execute in a separate lightweight routine to avoid delaying HTTP transfer responses.

## 5. Optional macOS Screenshot Directory Watcher

### 5.1 Motivation & Feature Scope
On macOS, users often take screenshots that save directly to disk (using Cmd+Shift+3 or Cmd+Shift+4) rather than copying directly to the clipboard (which requires holding the Ctrl modifier: Cmd+Ctrl+Shift+4). The optional watcher enables seamless syncing of file-based screenshots.

### 5.2 Location Discovery
- The watcher reads the user's custom screenshot destination by querying the system preference:
  - Command evaluated internally: defaults read com.apple.screencapture location
  - Fallback Destination: If no custom preference is set, defaults to the user's Desktop directory (/Users/[user]/Desktop).

### 5.3 Write Stability & Ingestion Logic
When a screenshot file is created:
1. Filesystem event monitor detects a newly created PNG file matching standard screenshot naming patterns.
2. The watcher enters a debounce loop, sampling file size across 250-millisecond intervals.
3. Once file size remains identical across two successive checks, the file write is deemed complete.
4. The watcher reads the raw PNG bytes, validates the PNG header via imaging, and passes the payload to the engine as an outbound image copy event.
5. This functionality is disabled by default and enabled exclusively when the operator specifies the --watch-screenshots flag.

## 6. Documentation Suite Specification

### 6.1 docs/SPEC.md
- Serves as the formal architectural reference for Clipdrop.
- Documents system goals, cryptographic invariants, trust models, and concurrency structures.
- Clarifies deliberate non-goals to prevent scope creep in future versions.

### 6.2 docs/protocol.md
- Serves as the complete wire protocol reference.
- Documents exact HTTP method specifications, endpoint routes, query parameters, and custom headers.
- Provides formal JSON schemas for ping responses, offer requests, offer responses, and error payloads.
- Defines binary streaming semantics and HTTP status code mappings.

### 6.3 docs/troubleshooting.md
- Structured as an operational runbook for diagnosing network and cross-platform issues:
  - Wi-Fi Access Point Client Isolation (preventing peer-to-peer multicast between laptops).
  - Windows Defender Firewall blocking inbound traffic on public Wi-Fi profiles.
  - macOS pasteboard and background notification prompts.
  - Diagnostic steps to verify mDNS packet flow using standard command-line tools.

## 8. Verification & Acceptance Testing Matrix

### 8.1 Automated Unit & Diagnostic Tests
- Doctor Port Collision Test: Open a temporary listener on port 47820. Run doctor port check. Verify check reports FAIL with guidance to use --port.
- Doctor Corrupted Identity Test: Truncate cert.pem. Run doctor identity check. Verify check reports FAIL with instructions to regenerate.
- Retention Limit Test: Ingest 25 dummy items into the retention manager. Verify that exactly the 20 newest files exist on disk and the 5 oldest were removed.
- File Sanitization Test: Pass malicious payload identifiers containing directory traversal strings (e.g., ../../etc/passwd). Verify retention manager sanitizes paths safely.

### 8.2 Manual Acceptance Tests
- Scenario 1 (Doctor Clean Host): Run clipdrop doctor on a properly configured machine. Verify all core checks return PASS in green.
- Scenario 2 (Doctor Windows Firewall): On Windows with blocked port, run clipdrop doctor. Verify the output provides the exact PowerShell command required to allow traffic.
- Scenario 3 (Received Items Pruning): Sync 22 sequential screenshots. Verify the received/ directory contains exactly 20 image files.
- Scenario 4 (macOS Screenshot Watcher): Launch clipdrop run --watch-screenshots on Mac. Press Cmd+Shift+4 and capture an area. Verify image automatically syncs to Windows clipboard without pressing Ctrl.
